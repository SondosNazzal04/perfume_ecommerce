# VELORA — تقرير تنفيذ تجديد الصفحات الداخلية (2026-11-01)

## قاعدة العمل
- الأساس: `VELORA_WINDOWS_SHORT_PATH(1).zip` (جذر المشروع داخل الأرشيف `V/`).
- اللاندينغ المعتمدة محفوظة: لم يتم تغيير تصميم الـHero أو أي قسم سينمائي آخر غير السائل الذهبي.
- ملفات المصادقة والـOTP الخلفية، قواعد البيانات، PHP Actions، APIs، الدفع، Google OAuth، إعدادات البريد، ووظائف الإدارة: **لم تُعدّل**.
- صفحة `verify-email.php` وكود `assets/js/velora-otp-ui.js`: **لم يتغيرا**.

## الإصلاحات المنفذة
1. أُضيف ملف `assets/css/velora-interior-v2.css` وارتبط بـ13 صفحة للعميل. يعالج تضارب الواجهات القديمة وتحويلها إلى هوية داكنة ذهبية موحّدة، ويكبّر النصوص والحقول والأزرار.
2. تمّ تجديد Shop: فلاتر داكنة، تصنيف مرئي واضح، أحجام مريحة للحقول، وتنسيق بطاقات ومعلومات المنتجات وWishlist والعمليات. تعود الأسعار والصور من API كما هي، لا توجد بيانات مزوّرة.
3. تمّ تحسين Product Detail، Cart، Checkout، Account، Wishlist، Orders، صفحات Login/Register والاستعادة، وFooter من ناحية التصميم فقط.
4. أُضيف `assets/css/velora-admin-v2.css` لرفع مقروئية الإدارة والجداول والإحصاءات والقوائم، عبر قالب الهيدر المشترك.
5. تمّ توحيد النص التسويقي الظاهر من Ater إلى VELORA في صفحات Shop/Account/Checkout وإزالة روابط تصنيف `sets` غير المضمون وجوده، مع إبقاء زر Collections يقود إلى المتجر الحقيقي.
6. صفحة اللاندينغ: أُضيف `src/gold-liquid-visibility.css` **فقط لقسمي السائل الذهبي** في Brand Story وNotes، لإزالة أقنعة متداخلة كانت قد تخفي أجزاء كبيرة من الفيديو. تم إضافة `gold-liquid-poster.webp` مستخرج من الفيديو الأصلي نفسه، مع تحسين preload / استئناف التشغيل بتعديل موضعي في `src/cinematic.js`. جميع مشاهد Hero ورشة العطر والشريط الذهبي الأصلية تُركت كما هي.
7. أضيفت حالات أوضح لفشل API ونتائج البحث الفارغة في `assets/js/storefront.js`، وزر إعادة المحاولة ومسح الفلاتر. لم يُعدّل أي Backend endpoint.
8. كان شريط التنقل يظهر كحبّة بيضاء على الكمبيوتر، والقوائم في الموبايل كانت تُضغط إلى 20px. اكتُشفت المشاكل خلال معاينة Chromium ثابتة، وعولجتا بقواعد CSS محددة، ثم أعيد الفحص.

## حدود الاختبار
- تم فحص صياغة 83 ملف PHP و18 ملف JS للمشروع.
- تم فحص مسارات الأصول المباشرة المستخدمة في الصفحة الرئيسية وصفحات التصفح والحساب والسلة.
- صور `docs/visual-qa/` هي معاينات مرئية **ثابتة** للـHTML الذي أعاده PHP، بعد إدخال CSS محليًا؛ لا تثبت تشغيل JS أو عمل API أو جلسات حقيقية، وتحوي Shop حالة مرئية تجريبية موضّحة في الصور.
- لا يمكن الإقرار بعمل API، OTP، Google Login، Stripe، أو قاعدة MySQL فعليًا من البيئة الحالية؛ `pdo_mysql` غير متاح في PHP هنا، وعناوين localhost محجوبة في المتصفح الآلي. الرجاء تجربة الوظائف على Windows مع PHP 8.2 وMySQL.

## خطوات المعاينة على جهاز Windows
1. فك ZIP مباشرةً في `C:\`، ليصبح جذر المشروع `C:\V` (المسار قصير لتفادي `0x80010135`).
2. افتح مجلد `C:\V` في VS Code، وشغّل MySQL من XAMPP.
3. جهّز قاعدة بيانات اختبار معزولة `perfume_ecommerce`، واستورد نسخة SQL الكاملة التي قدمها الفريق **بعد أخذ نسخة احتياطية**؛ لا تستورد بيانات أشخاص حقيقية في بيئة عامة.
4. شغّل PHP Server من VS Code، أو من مجلد `C:\V` نفّذ: `& "C:\xampp\php\php.exe" -S 127.0.0.1:8000 -t .`.
5. افتح `http://127.0.0.1:8000/index.php` ثم `products.php` ثم `login.php` و`cart.php` و`admin/index.php` حسب صلاحياتك.
6. إذا ظهرت `0 fragrances` مع بيانات في MySQL، افتح `/api/storefront-products.php` في المتصفح وF12 → Network لمعرفة استجابة API الحقيقية؛ لا تغيّر API في هذه النسخة.

## ملاحظات الفريق
- Google Login: في فيديو المستخدم السابق انتهت العودة من Google بخطأ 404. راجع مع فريق Backend إعداد OAuth callback والـURI المطابق لمسار تشغيل التطبيق. لا تعالج ذلك بإعادة تصميم زر Google.
- متجر يعرض صفر منتجات: تحقق من SQL الفعلي وصحة اتصال PDO ومن وجود بيانات المنتجات ومتغيراتها والصور، وراجع Response من `api/storefront-products.php`.
- لا تختبر معاملات دفع حقيقية دون ضبط Stripe Test Mode.
- أرشيف التيم يتضمن إعدادات تكامل ومكتبات. لا تنشره إلى GitHub عام قبل مراجعة الأسرار وبيانات المستخدمين.
